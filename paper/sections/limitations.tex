\section{Limitations and threats to validity}
\label{sec:limitations}

We state these plainly, because several of them bound how strongly the
comparison can be read.

\paragraph{One training seed per arm in the main campaign.}
The v4 frontiers come from one training run per arm. The test-split confidence
intervals capture sentence and task-model sampling variation, but not
\emph{training-seed} variation, which in this problem is large for GRPO: in the
three-seed v3 campaign its seeds spanned $26.3$--$34.7$ mean reward, against
$36.8$--$40.0$ for \rrebel{} (Section~\ref{sec:seed-replication}). The v3
replication supports the \emph{family} ordering across seeds, but it was
measured on a $10$-sentence development set. A multi-seed test-split
replication of v4 is the most important missing experiment.

\paragraph{GRPO in the single-update regime.}
Both GRPO arms take one gradient step per rollout, so the PPO clip is inert
(Section~\ref{sec:grpo}) and the KL term is the only regularizer. The base-LM
reference arm removes the earlier confound that GRPO's anchor was uniform (an
entropy bonus rather than a trust region). It does not test GRPO with multiple
epochs per rollout, where the clip is live, and $\beta_{\mathrm{KL}}$ was not
swept. Our claims are about GRPO in this regime, not about GRPO in general.
Corollary~\ref{cor:grpo} sharpens what the comparison isolates: at $K=1$,
\rrebel{}-$\ell_2$-std \emph{is} KL-free GRPO. The measured gap is therefore
attributable to the reference lag and the discrepancy, the two ingredients
\rrebel{} adds.

\paragraph{The theory is idealized.}
Section~\ref{sec:theory} analyses population quantities: exact reward
expectations, the population reward standard deviation, and reference windows
solved to optimality. The implementation uses $16$-sample standard deviations,
a moving sampler within each window, and $150$ Adam steps per window. The gaps
are listed at the end of Section~\ref{sec:theory}. No experiment here ablates
standardization directly, since every \rrebel{} arm uses it; the evidence for
Section~\ref{sec:th-std} is the toy computation of
Figure~\ref{fig:theory-toy} together with the reward-scale measurement of
Section~\ref{sec:res-scale}.

\paragraph{The reward is a surrogate for the constraint.}
The constrained reward penalizes each task-model sample that falls below the
floor. It is therefore a surrogate for a \emph{chance} constraint, not a
guarantee that expected content meets the floor. Section~\ref{sec:res-control}
measures how closely each policy honours the floor. The penalty constant
($0.01$) was not tuned, and it shapes where violations are traded against
sentiment.

\paragraph{Optimizer state does not survive a resume.}
Checkpoints store model parameters only, and the optimizer is rebuilt on each
resume. Every run is thus a sequence of Adam warm restarts with zeroed moments:
$26$--$31$ productive $4$-hour cycles per v4 arm. The counts are similar across
arms, so this is not a systematic handicap to either family, but it is a
methodological defect. It also blocks the obvious scheduling improvement:
shorter cycles would queue faster but would multiply the warm restarts.

\paragraph{Heterogeneous hardware.}
Training cycles ran on whichever eligible GPU was free (H100, L40S, A100,
RTX~A6000, RTX~6000 Blackwell). Different GPUs execute different kernels, so
runs are not bit-reproducible. We have no evidence that this affects any arm
systematically.

\paragraph{The style classifier used at evaluation.}
The evaluation entry point loads the \emph{train}-split style classifier (the
only one available locally). The same classifier scores every arm, so this
cannot explain differences between arms, but absolute sentiment numbers are not
comparable to work that evaluates with a held-out classifier.

\paragraph{Single task and single direction.}
All results are Yelp negative-to-positive, with a \texttt{gpt2-xl} task model and
$5$-token prompts. We make no claim about other datasets, transfer directions,
prompt lengths, or larger task models.
